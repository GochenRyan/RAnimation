# 资产规范

适用：RAnimation 发布资产。当前运行时限制以 SkeletalAnimBehavior 为准。

## 1. 坐标与单位

| 项目 | 要求 |
| --- | --- |
| 坐标系 | 右手系，+Y 向上 |
| 长度单位 | 米；USD `metersPerUnit = 1` |
| USD 上轴 | `upAxis = "Y"` |
| 角色默认朝向 | 前方 −Z、右方 +X、上方 +Y |
| 角色模型原点 | 地面上的角色定位点；世界放置由实例变换控制 |
| 网格正面 | `orientation = "rightHanded"`；从正面观察为 CCW |
| 数值 | 位置、旋转、缩放、权重必须有限，不得包含 NaN 或 Inf |

DCC 源文件可以使用厘米或米。发布结果必须符合上述要求，角色实际尺寸由源模型决定，不要求人物高度为 1 米。

## 2. 角色变换与缩放

- 发布角色的静态缩放为 `(1, 1, 1)`，包括资产根、Armature、骨架祖先、网格及关节静止姿态中的缩放。
- 标准角色动画不携带缩放轨道；存在缩放采样时，其值必须为 `(1, 1, 1)`。有意使用骨骼缩放的资产须另行声明支持范围并通过专项验收。
- 不得残留用于单位转换的 `100`、`0.01` 等祖先缩放，也不得通过相互抵消的父子缩放满足检查。
- 验收须检查局部变换及累计变换。实例缩放为 1 时，静止姿态下各关节模型空间矩阵的三个基轴须单位正交，行列式为正。
- 不允许剪切、退化基轴或镜像变换。DCC 镜像建模结果须在发布前烘焙，并修正绕序和法线。
- 场景中的角色实例仅使用正的统一缩放。实例缩放用于调整人物尺寸，不用于修补资产单位。

缩放归一必须同步处理网格顶点、关节平移、绑定变换及动画平移。不得仅将父节点 `scale` 改为 1；不得将全部字段无差别乘同一个系数。

归一前后，在相同实例变换和相同动画时刻，角色的最终尺寸、关节位置及蒙皮表面必须保持一致。

## 3. 网格与蒙皮

- 发布网格使用三角形；不得依赖运行时扇形剖分处理凹多边形。
- 法线须与发布后的几何和绕序一致。变换烘焙时按逆转置变换法线并归一化。
- UV 使用 `primvars:st`。当前加载器执行一次 V 翻转，发布端不得额外为该路径预翻转。
- 每个蒙皮顶点最多保留 4 个非零骨骼权重；权重非负、总和为 1，至少有一个有效影响。
- 骨骼索引必须有效；网格的关节映射必须与绑定骨架一致。
- `geomBindTransform`、`bindTransforms`、`restTransforms` 必须使用一致的空间与单位。绑定矩阵必须可逆，不要求其为单位矩阵。
- 当前角色加载路径只读取首个 Skeleton 和首个 Mesh。发布角色须提供单骨架、单蒙皮网格；多网格角色须先合并或扩展加载器。
- 贴图及材质引用必须可解析；当前纹理路径不视为完整的 USD 材质网络支持。

## 4. 骨架与动画

- 关节路径唯一、层级无环；供代码按短名查询的关节，其短名也必须唯一。
- `joints`、静止变换、绑定变换及动画通道的对应关系必须明确，不得依赖不同文件恰好具有相同的数组顺序。
- 同一角色的动画片段必须匹配同一骨架层级和静止姿态。额外 FBX 的骨架不匹配时拒绝合并。
- 旋转四元数必须归一化；轨道时间递增；帧率和时间码元数据必须明确。
- 片段名称和元数据映射必须稳定，能够被 profile、动画图和行为树正确引用。
- 当前 CharacterController 使用代码位移，发布移动动画采用 in-place 版本。根运动动画不得直接接入该路径。
- 资产更新后须重建 TRS 纹理等派生缓存，不得混用旧缓存与新骨架或新动画。

## 5. 相机挂点

- 第一人称使用明确的头部关节名；当前默认名称为 `Head`。
- 头骨局部轴不默认等于角色朝向。接入新模型时须核对头部轴向与相机朝向。
- 头部世界位置使用完整层级变换的结果。
- 相机方向仅使用从头部世界矩阵提取的单位旋转；视图矩阵不得携带骨骼缩放或剪切。
- `eyeOffset` 为头部坐标轴下的米制偏移，`forwardPush` 为观察方向上的米制偏移；两者以实例缩放为 1 的人物尺寸配置，运行时只乘一次实例缩放。
- 骨骼中的单位换算缩放不得作用于相机偏移；投影参数不随角色缩放变化。

## 6. 静态场景

- 静态场景不包含 Skeleton；显示网格与角色资产分开发布。
- 几何、碰撞体、区域和标记的位置均按完整 `LocalToWorld` 及 Stage 单位、上轴转换解释，不得仅读取局部平移。
- DCC 导出的静态中间层允许携带单位或轴向转换根节点；加载后所有空间数据必须落入同一米制世界。
- 静态实例与动态角色分层保存，关卡引用使用 `.static.usda` 与 `.level.usda`。
- 碰撞体、区域及标记使用约定的 `ranim:*` 属性，属性类型必须与加载器一致。

## 7. 文件与依赖

```text
<角色目录>/
  <名称>.asset.usda
  <名称>.profile.json
  model/
  anim/
  metadata/
  baked/
```

- 资产入口须声明 `defaultPrim`，并正确引用模型及动画元数据。
- 资产内部依赖使用相对路径，不得包含发布机器的盘符、用户目录或临时路径。
- 交付必须包含全部被引用的 USD 层、动画、元数据、贴图及运行所需缓存。
- 发布过程保留源 DCC／FBX 文件；新产物通过验收后再替换正式资产。

## 8. 发布验收

| 检查项 | 通过条件 |
| --- | --- |
| 元数据与引用 | 单位、上轴、入口正确；全部依赖可解析 |
| 尺寸与朝向 | 实例缩放 1 时符合源模型实际尺寸，正面朝 −Z |
| 静态缩放 | 局部缩放各分量与 1 的误差不超过 `1e-4`；累计基轴长度误差、轴间点积绝对值不超过 `1e-4`；行列式为正 |
| 归一等价性 | 在同一米制坐标系比较，包围盒、对应关节与对应蒙皮顶点的位置误差不超过 `1e-4 m`；每个片段至少检查首尾及全部导出采样时刻 |
| 蒙皮绑定 | 无无效索引、负权重、零权重总和或不可逆绑定矩阵；权重总和误差不超过 `1e-4` |
| 动画与缓存 | 片段引用有效；派生缓存由本次资产生成；CPU／GPU 蒙皮验证通过项目容差 |
| 相机 | 实例缩放 `0.5 / 1 / 2` 时位置合理；偏移按实例缩放变化；视图基轴保持单位正交 |
| 静态场景 | 渲染几何、碰撞体、区域和标记在最终世界空间对齐 |

未通过的资产不得替换正式发布版本。
